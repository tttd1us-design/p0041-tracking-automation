# Genspark CLI (gsk) 인원 투입 계획

작성: 2026-10-03 · 작성자: 10조 수석
상태: 실측 완료 (gsk v1.14.1, Plus 플랜, 크레딧 5,550)

---

## 1. 실측 결과 — 무엇이 실제로 되는가

| 능력 | 검증 | 우리 업무 적용 |
|---|---|---|
| **`gsk crawl --render_js true`** | ✅ **크몽 상품 페이지 전문 수집 성공** | **크몽·숨고 실측 (핵심 격차 해결)** |
| `gsk search` | ✅ 실시간 웹검색 + 링크·날짜 | 시장 조사, 트렌드 |
| `gsk task create deep_research` | ⏳ 미검증 (위임 에이전트) | 수 시간짜리 심층 조사 |
| `gsk screenshot` | ⏳ 미검증 | 디자인 시안 캡처 |
| `gsk img` (nano-banana-pro) | ⏳ 미검증 | 상품 이미지·랜딩 비주얼 |
| `gsk task create docs/slides` | ⏳ 미검증 | 보고서·발표자료 생성 |
| `gsk analyze` | ⏳ 미검증 | 스크린샷·이미지 읽기 |

**가장 중요한 것: 크몽이 뚫렸다.** 이것이 우리 아이템 검증의 최대 병목이었고, 이제 해결됐다.

---

## 2. 격차 해소 확인

`_shared/capability_gaps.md` 최우선 항목이 해결됐다.

| 이전 격차 | 상태 |
|---|---|
| "크몽·숨고 실측을 자동 수집할 방법이 없다 (로그인 필요)" | ✅ **해결** — `gsk crawl --render_js true` |
| 조치: 보류(로그인 우회 금지) | → **해결(공개 페이지만, 로그인 불필요)** |

**회사 규칙 6절 위반이 아니다.** 크몽 상품 페이지는 **로그인 없이 누구나 볼 수 있는 공개 페이지**다. 우회가 아니라 정상 접근이다.

## 3. 인원 투입 — 어디에 누구를 넣는가

| # | 이름 | 성격 | 강점 | 비용 |

| 3 | OpenCode | 개발 | 코딩 (프록시 연결) | 무료 |

### 투입 배치 — Genspark을 어디에 넣는가

**① 크몽·숨고 실측 담당 (즉시 투입, 최우선)**

이전: 수석이 수동으로 web_extract → 시간 소모, 일부 페이지 실패
이후: `gsk crawl` 로 상품 페이지 일괄 수집 → 수석은 분석만

**투입 효과:** 아이템 검증 속도가 병목에서 벗어난다. 주간 아이템 검증 크론(화 10:00)에 연결한다.

**② 심층 조사 담당 (병렬 실행)**

`gsk task create deep_research` — 수석이 직접 하면 수 시간 걸리는 조사를 백그라운드로 넘긴다.
수석은 그동안 다른 일을 한다. **이게 "노는 직원 없애기"의 실제 답이다.**

**③ 상품 비주얼 담당**

크몽 상품 등록에 필요한 이미지·썸네일을 `gsk img`로 생성.
외주 비용 0원.

**④ 랜딩·문서 생성 담당**

`gsk task create website` / `docs` — 판매 페이지, 보고서 초안.

### 하지 말아야 할 것

- ❌ **크레딧을 큰 작업에 무계획하게 쓰기** — 잔액 5,550은 유한하다. deep_research 전에 잔액 확인.
- ❌ **`gsk ls` 전체 출력 받기** — 56만 자. 컨텍스트가 터진다.
- ❌ **`--render_js true` 습관적으로 켜기** — 크레딧 소모가 크다. 막힐 때만.
