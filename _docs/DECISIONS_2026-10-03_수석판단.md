## 2. 수석 판단

### 판단 1: 브리지 추가 안정화 — **즉시 적용**

**결정:** 클로드가 제안한 **상태기반 완료판정**을 적용한다.

**이유:**
- 현재 "응답이 2회 연속 같으면 완료" 방식은 스트리밍 응답에서 과대기 발생
- 추출 실패가 timeout으로 위장되는 문제가 있음
- protobuf wire-format 파싱은 적용했지만, 완료판정 로직은 개선 필요

**적용 내용:**
- `wait_reply()` 함수에 상태기반 완료판정 추가
- 추출 실패 시 명시적 에러 반환 (timeout 위장 방지)
- payload 길이/해시 로깅 추가

### 판단 2: MoA 작동 테스트 — **즉시 실행**

**결정:** `/moa` 명령을 실제로 실행해서 작동 여부를 확인한다.

**이유:**
- 설정만 변경하고 작동 테스트를 하지 않음
- 무료 모델 3개가 실제로 응답하는지 확인 필요
- 실패 시 폴백 체인으로 자동 전환되는지 확인

### 판단 3: rate limit 재시도 — **지연 실행**

**결정:** step-3.7-flash 모델의 rate limit이 해제된 후 재시도한다.

**이유:**
- 429 에러는 일시적 (retry_after: 3262초 ≈ 54분)
- 즉시 재시도해도 같은 결과
- 다른 작업 먼저 진행 후 나중에 확인

### 판단 4: 안티그래비티 프로세스 안정화 — **모니터링 강화**

**결정:** 안티그래비티 프로세스 상태를 정기적으로 확인하는 크론을 추가한다.

**이유:**
- 게이트웨이 셧다운 시 프로세스가 종료됨
- 브리지 사용 전 프로세스 상태 확인 필요
- 자동 재시작 로직 추가

### 판단 5: 다음 우선순위 — **Merge10 상업화**

**결정:** 기술 인프라 안정화 후 Merge10 외부 배포 + 결제 연동에 집중한다.

**이유:**
- 기술 문제는 대부분 해결됨
- 매출 0원 → 첫 판매 경로가 최우선
- 대표 승인 대기 중: 외부 배포, 결제 연동, 도메인 구매
