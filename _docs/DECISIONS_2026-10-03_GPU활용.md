## 2. 수석 판단 (5건)

### 판단 1: ollama 설치 — **즉시 실행**

**결정:** ollama를 설치하고 소형 모델을 다운로드한다.

**이유:**
- 무료 오픈소스, 비용 0원
- GPU 6GB 활용 가능
- 외부 API 의존도 감소
- 오프라인 작업 능력 확보

**조치:** 설치 → 모델 다운로드 → 테스트 추론.

### 판단 2: 모델 선택 — **소형 모델 우선**

**결정:** 1-3B 파라미터 모델을 우선 도입한다.

**이유:**
- GPU 6GB 제한: 7B 모델은 양자화 시 4-6GB로 위험
- 1-3B 모델은 2-4GB로 안정적
- 불편 분석·요약 등 업무에 충분

**선택 후보:**
| 모델 | 파라미터 | 크기 | 용도 |
|------|----------|------|------|
| llama3.2:1b | 1B | ~0.8GB | 간단 분석 |
| llama3.2:3b | 3B | ~2GB | 불편 분석·요약 |
| phi3:mini | 3.8B | ~2.5GB | 범용 |
| qwen2.5:1.5b | 1.5B | ~1GB | 한국어 지원 |

### 판단 3: 활용 처리 — **불편 분석·요약 자동화**

**결정:** 로컬 모델로 불편 데이터 분석·요약을 자동화한다.

**이유:**
- 외부 API 호출 비용 절감
- 오프라인 처리 가능
- 크론으로 주기적 실행 가능

**조치:** 로컬 모델 기반 불편 분석 스크립트 작성.

### 판단 4: 모니터링 — **GPU 사용률 모니터링 크론 추가**

**결정:** GPU 사용률을 모니터링하는 크론을 추가한다.

**이유:**
- 자원 사용 가시화
- 과부하 방지
- 로컬 모델 실행 상태 확인

**조치:** `gpu_monitor.py` 작성 → 크론 등록.

### 판단 5: 보안 — **로컬 모델은 외부 전송 없음**

**결정:** 로컬 모델 추론은 외부 데이터 전송이 없음을 보장한다.

**이유:**
- 회사 규칙: 비밀값은 코드·문서·git에 넣지 않음
- 로컬 추론은 데이터가 브라우저 밖으로 나가지 않음
- 안티그래비티와 동일한 보안 원칙 적용

**조치:** 로컬 모델 사용 시 외부 API 호출 없음을 코드로 보장.
