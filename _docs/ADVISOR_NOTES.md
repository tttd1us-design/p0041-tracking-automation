# 고문 메모 (Claude → 10조 수석)

고문(Claude)이 10조 수석에게 남기는 조언이다. **실제 업무는 10조 수석이 한다.** 고문은 검토하고 조언할 뿐 대신 일하지 않는다.

## 사용법

- 10조 수석은 업무를 시작할 때 아래 **열린 조언**을 확인한다.
- 조언을 반영했으면 상태를 `반영함 (YYYY-MM-DD, 한 줄 결과)`로 바꾸고, 반영하지 않기로 했으면 `보류 (이유)`로 적는다. 조언을 지우지 않는다.
- 고문에게 상담이 필요하면 맨 아래 **수석의 질문**에 적는다. 대표가 고문을 부를 때 함께 검토한다.
- 대표의 결정이 고문의 조언보다 우선한다.

### A-002 · 엑셀 아이템의 기획 추가 검증 — 상태: 열림 (대표 결정: 개발 보류, 기획 더 검증 먼저)
> 고문 메모(10/3): `specs/draft/excel-auto-transform/validation.md`와 `01_pain_mining/reports/2026-10-03_크몽숨고_검증.md`가 이미 있다. 반영했다면 상태를 '반영함'으로 바꾸고 결론(진행/보류/중단)을 한 줄 적어라.
명세의 가장 큰 약점은 **"실제로 돈을 낼 사람이 있다는 근거가 없음"**이다. 개발 없이 이것부터 확인하라. 권하는 순서:
1. **이미 돈이 오가는 증거**: 크몽·숨고 등에서 "엑셀 자동화" 의뢰·서비스의 가격대, 판매 건수, 리뷰 수. 사람들이 이 일에 이미 돈을 낸다면 가장 강한 근거다.
2. **경쟁 제품의 실적**: 명세에 나온 경쟁 제품들의 사용자 수·리뷰·가격 변화. 경쟁자가 돈을 벌고 있으면 시장이 있다는 뜻이다.
3. **구체적 사용 장면**: 구글 플레이 리뷰·네이버 블로그에서 "매주 ○○ 취합" 같은 반복 업무의 실제 사례를 5개 이상.
4. **판단 기준을 먼저 정하고 조사**: 예) "유사 서비스가 월 1만 원 이상에 팔리고 있고 판매 실적이 보이면 진행". 조사 후에 기준을 맞추지 않는다.

결과는 `02_product_spec/specs/draft/excel-auto-transform/validation.md`에 쓰고, 대표에게 **진행 / 보류 / 중단** 중 하나를 근거와 함께 권한다. 랜딩페이지로 관심도를 재는 방법도 있지만 외부 공개라 게이트 3 승인이 필요하다 — 조사 결과를 보고 대표가 원하면 그때 제안한다.
