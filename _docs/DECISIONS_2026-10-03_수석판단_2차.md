## 2. 수석 판단 (7건)

### 판단 1: 배포 전 필수 요건 — **약관 확정**

**결정:** 약관의 `[대표 확인 필요]` 4곳을 **대표 확인 요청 항목으로 분리**하고, 확인 즉시 반영할 수 있게 준비한다.

**이유:**
- 법률 검토 전 배포는 리스크. 그러나 무한 대기는 기회비용 손실.
- 4곳은 모두 **사실 정보**(사업자명·연락처)로, 대표만 알 수 있다.
- 나머지 조항은 이미 완성되어 있어 4곳만 채우면 배포 가능.

**조치:** 대표에게 4개 항목을 한 번에 질문 (아래 5절).

### 판단 2: 주 모델 반복 루프 — **폴백 우선순위 재조정**

**결정:** `gemini-3.8-flash`를 주 모델로 유지하되, 반복 루프 발생 시 **자동 폴백이 작동하는지 검증**한다.

**이유:**
- 주 모델을 바꾸면 품질 저하 위험 (gemini가 가장 우수)
- 반복 루프는 간헐적 문제 — 폴백이 제대로 작동하면 치명적이지 않음
- 크론은 이미 모델 고정 완료

**조치:** 폴백 8개 실제 응답 테스트 → 죽은 모델 제거/교체.

### 판단 3: MoA 활성화 — **보류**

**결정:** MoA를 켜지 않는다.

**이유:**
- 현재 `Active in config: (off)` — 의도된 상태
- MoA는 매 호출마다 여러 모델을 돌려 **비용·지연 증가**
- 무료 모델만 쓰는 현 체제에서 MoA는 이득보다 리스크
- 크론 13개가 이미 병렬 업무를 수행 중

**조치:** 설정 유지. 필요 시 개별 호출로 사용.

### 판단 4: 크론 모델 표준화 — **즉시 적용**

**결정:** 모든 크론에 **무료 모델을 고정**한다.

**이유:**
- 시간당 보고가 주 모델 변경에 휩쓸려 실패한 사례
- 크론은 반복 작업이므로 모델 안정성이 품질보다 중요
- 무료 모델로 충분한 작업(집계·백업·모니터링)이 대부분

**조치:** 크론 13개에 `model=meituan/longcat-2.5-preview:free`, `provider=nous` 일괄 적용.

### 판단 5: 배포 사전 준비 — **즉시 실행**

**결정:** 승인 전에 **배포 실행 계획과 검증을 완료**한다.

**이유:**
- 승인 즉시 1일 내 배포가 목표
- 승인 후 준비하면 시간 낭비
- 사전 준비는 외부 공개가 아니므로 게이트 위반 아님

**조치:**
- 빌드 재검증 ✅ (방금 완료, 3/3 export)
- 검증 스크립트 ✅ (전 항목 통과)
- 배포 경로 확정 (Cloudflare 임시 배포 — 계정 불필요)
- DEPLOY_LOG 초안 작성
- 출시 홍보 계획 초안

### 판단 6: 두 번째 제품 — **보류**

**결정:** Merge10 배포 전에는 2호 제품 기획을 시작하지 않는다.

**이유:**
- 매출 0원 상태에서 제품 추가는 자원 분산
- 첫 제품의 시장 반응을 봐야 다음 판단이 가능
- "안 팔리면 필요없어" 원칙

**조치:** 배포 후 첫 고객 반응 확인 → 그 다음 기획.

### 판단 7: 보고 체계 — **안정화 확인**

**결정:** 17:00 시간당 보고가 정상 작동하는지 확인하고, 실패 시 즉시 대응한다.

**이유:**
- 16:00 실패 후 조치했지만 검증 안 됨
- 대표 보고에 차질이 없어야 함

**조치:** 17:00 실행 결과 확인.
